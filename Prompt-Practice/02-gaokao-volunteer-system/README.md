# 🎓 高考志愿填报系统实战教程

> 以“高考成绩发布后的志愿填报辅助系统”为例，整理一套可直接用于生成 skill 前置材料的 Prompt 实战文档

---

## 📌 项目背景

目标是开发一个支持 PC 和 H5 访问的 Web 系统，在学生拿到高考分数后，结合成绩、位次、选科、兴趣方向、目标城市、院校偏好、专业倾向等信息，输出更适合的志愿填报建议与方案对比。

本次实战不直接写业务代码，而是先沉淀 3 份高质量 Prompt 文档，作为后续生成 skill、继续做需求分析、系统设计和开发规划的基础输入。

## 🧭 本次实战过程记录

### 第1步：明确业务目标

先把原始想法整理成明确项目目标：

- 做一个“高考志愿填报辅助”的 Web 系统
- 在出分后帮助学生进行院校和专业筛选、组合和对比
- 输入要覆盖分数、位次、兴趣、城市、学校层次、专业偏好等关键因素
- 输出要强调“辅助决策”，不是替代学生做最终志愿决定

### 第2步：拆分核心功能

把需求拆成 4 组核心能力：

1. **学生信息采集与画像**
   - 高考分数
   - 位次或排名
   - 所在省份与批次
   - 选科组合
   - 兴趣方向
   - 目标城市与学校偏好

2. **志愿推荐与方案生成**
   - 根据分数与位次筛选可报院校和专业
   - 根据兴趣、城市、专业倾向进行二次匹配
   - 输出“冲、稳、保”分层建议
   - 支持多套志愿方案对比

3. **院校与专业信息整合**
   - 历年录取分数/位次参考
   - 招生计划与选科要求
   - 学校层次、地域、办学类型、专业特点
   - 风险提示与说明

4. **多端展示与交互**
   - PC 与 H5 自适应
   - 适合学生与家长快速理解
   - 支持筛选、比较、收藏、方案导出

### 第3步：将项目拆成 3 类 Prompt

为了让后续 skill 更容易生成与复用，将文档拆成 3 类：

1. **需求提示词**
   - 让模型输出完整需求文档
   - 明确用户角色、核心流程、推荐边界、数据约束、免责声明

2. **系统设计提示词**
   - 让模型输出系统架构、数据模型、推荐逻辑、接口与前端结构

3. **开发计划提示词**
   - 让模型输出阶段目标、任务拆解、迭代节奏、测试与验收方案

### 第4步：约束 Prompt 的输出格式

为了后续更容易转成 skill，本次 Prompt 文档统一遵循以下原则：

- 输出结构固定
- 明确输入、输出、规则、限制
- 强调省份差异、年份差异和批次差异
- 强调数据可信性与时效性
- 明确免责声明、风险提示和待确认项

## 🧱 后续如何扩展

未来你继续建立新的实战目录时，可以直接复用本目录的方法：

1. 先写一个项目 README，记录目标和拆解过程
2. 固定输出 3 份 Prompt 文档
3. 后面再补充 skill 生成文档或提示词迭代记录

这样每个项目都能形成一套标准化、可复用、可沉淀的 Prompt 教程资产。
