# 📈 热门股票 Web 系统实战教程

> 以“实时热门股票分析与整理系统”为例，整理一套可直接用于生成 skill 前置材料的 Prompt 实战文档

---

## 📌 项目背景

目标是开发一个可同时支持 PC 和 H5 访问的 Web 系统，用于在开盘、午盘、收盘三个时间段，分析和整理 A 股市场中的实时热门股票、热门板块和热门题材。

本次实战不直接写业务代码，而是先沉淀 3 份高质量 Prompt 文档，作为后续生成 skill、再驱动需求分析、系统设计和实施规划的基础输入。

## 🧭 本次实战过程记录

### 第1步：明确业务目标

将原始需求先还原成一个清晰业务目标：

- 做一个“实时热门股票分析与整理”的 Web 系统
- 数据要来自证券交易系统及券商公开数据
- 页面要美观，支持 PC 和 H5
- 最终不是直接让模型写代码，而是先产出后续可生成 skill 的标准化 Prompt 文档

### 第2步：拆分核心功能

把需求拆成 4 组核心能力：

1. **分时段热门股票采集**
   - 开盘
   - 午盘
   - 收盘
   - 分别覆盖沪指、深成指、创业板
   - 输出成交量最活跃 20 只、成交额最多 20 只

2. **板块与题材热度分析**
   - 根据上涨/下跌比例统计热门板块、热门题材
   - 列出 10 个热门板块/题材
   - 列出 10 个下跌板块/题材

3. **可信数据源约束**
   - 必须基于真实、可靠、公开可获取的数据
   - 优先强调交易所、证券行情系统、券商公开接口或合规数据服务

4. **多端展示能力**
   - PC 与 H5 自适应
   - 更偏金融看板风格
   - 兼顾实时性、可读性与可视化

### 第3步：将项目拆成 3 类 Prompt

为了让后续 skill 更容易生成与复用，将文档拆成 3 类：

1. **需求提示词**
   - 让模型把项目需求澄清完整
   - 输出角色、用户场景、功能边界、数据边界、非功能约束

2. **系统设计提示词**
   - 让模型产出系统架构、数据流、模块划分、接口设计、展示方案

3. **开发计划提示词**
   - 让模型产出分阶段任务、人员分工、里程碑、风险与验收方案

### 第4步：约束 Prompt 的输出格式

为了后续更容易转成 skill，本次 Prompt 文档统一遵循以下原则：

- 输出结构固定
- 字段尽量完整
- 强调可执行和可落地
- 明确风险、假设、待确认项
- 避免模型跳过数据合规与可靠性问题

## 🧱 后续如何扩展

未来你继续建立新的实战目录时，可以直接复用本目录的方法：

1. 先写一个项目 README，记录目标和拆解过程
2. 固定输出 3 份 Prompt 文档
3. 后面再补充 skill 生成文档或提示词迭代记录

这样每个项目都能形成一套标准化、可复用、可沉淀的 Prompt 教程资产。
