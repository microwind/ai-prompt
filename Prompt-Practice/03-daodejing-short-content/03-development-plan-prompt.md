# 🛠️ 《理解道德经》短内容改写生产计划提示词

> 用于让模型根据需求文档和内容设计文档，输出一份阶段化、可执行的批量生产计划

---

## 📌 适用场景

当你已经有了需求分析和内容设计结果，希望 AI 帮你进一步拆出批量执行路线、章节分批策略、校对流程、质量控制与发布节奏时，可以使用本提示词。

---

## 🎯 Prompt 目标

让模型输出：

- 项目实施阶段划分
- 批量生产任务清单
- 分批处理建议
- 复核与质检方案
- 发布节奏建议

---

## ✅ 完整 Prompt 模板

```markdown
你是一位资深内容项目经理，擅长把需求文档和内容设计文档拆解成一份可执行的批量生产计划。

现在我要把《理解道德经》按章节改写成适合小红书、微头条、知乎发布的简洁版本。我已经有需求分析和内容设计方案，请你基于这些材料输出一份完整的生产计划。

【输入材料1：需求分析】
{在这里粘贴需求分析结果}

【输入材料2：内容设计】
{在这里粘贴内容设计结果}

【项目目标】
基于 `/Users/jarry/github/daodejing/notes/` 下的章节原稿，按章生成简洁版内容，适配小红书、微头条、知乎，并保持全书风格统一、表达稳定、尽量忠于原意。

【规划要求】
1. 将项目拆分为明确阶段，例如：
   - 规则确认
   - 样章试产
   - 模板定稿
   - 批量生产
   - 复核修订
   - 发布整理
2. 每个阶段都要说明：
   - 目标
   - 关键任务
   - 产出物
   - 前置依赖
   - 风险点
3. 给出适合 81 章内容的分批处理建议
4. 给出首批试产章节建议和原因
5. 输出 MVP 范围优先级，区分“先做样章”和“后续批量全量生成”
6. 给出适合 1-3 人执行的小团队分工建议
7. 给出质量控制流程，包括内容准确性、风格统一性、平台适配性校验
8. 给出发布前检查清单

【特别约束】
1. 不要把计划写成技术开发排期，而要贴合内容生产项目
2. 要重点考虑章节之间风格统一和原意偏差控制
3. 要考虑不同平台的改写深浅差异
4. 生产计划要体现“先样章验证，再批量铺开”的节奏
5. 输出要足够清晰，方便我继续转成 skill 或操作清单

【输出格式】
请严格按以下结构输出：

# 生产计划

## 1. 项目实施目标

## 2. MVP 范围定义
- 首批样章
- 批量生产范围
- 二期可扩展

## 3. 阶段划分
### 阶段1
- 目标
- 关键任务
- 产出物
- 前置依赖
- 风险点

### 阶段2
- 目标
- 关键任务
- 产出物
- 前置依赖
- 风险点

## 4. 任务拆解清单
- 内容提炼任务
- 改写任务
- 校对任务
- 发布整理任务

## 5. 分批处理建议

## 6. 团队角色与分工建议

## 7. 执行排期建议
- 第1阶段
- 第2阶段
- 第3阶段

## 8. 质量控制流程
- 原意校验
- 风格校验
- 篇幅校验
- 平台适配校验

## 9. 发布前检查清单

## 10. 风险控制与应对预案

## 11. 验收标准

请使用专业、清晰、可执行的中文输出。
```

---

## 💡 使用建议

- 先用前两份 Prompt 拿到需求分析和内容设计结果，再作为本 Prompt 的输入
- 如果你想先做 10 章样章，也可以在输入里明确首批章节范围
- 如果你准备后续自动生成 skill，本文件特别适合作为“批量任务编排”和“质检流程”的来源

---

## 🧪 推荐补充参数

你可以在输入里追加这些信息，让计划更贴近实际：

- 首批样章数量：5 章 / 10 章 / 20 章
- 主发平台： 头条 / 小红书 / 微信公众号 / 知乎
- 一稿多发
- 人工终审
- 需要配图文案
