# 🧾 高考志愿填报系统需求提示词

> 用于让模型输出一份完整、可落地、可继续进入系统设计阶段的需求分析文档

---

## 📌 适用场景

当你要开发一个“高考志愿填报辅助系统”，希望 AI 先帮你完成需求澄清、功能拆解、数据边界确认、推荐边界约束、非功能要求整理时，可以使用本提示词。

---

## 🎯 Prompt 目标

让模型输出：

- 完整项目目标
- 用户角色与使用场景
- 志愿推荐流程与功能需求
- 数据需求与可信性要求
- 推荐边界与免责声明
- 风险、假设和待确认问题

---

## ✅ 完整 Prompt 模板

```markdown
你是一位资深教育产品经理兼高考志愿填报咨询系统顾问，擅长将模糊业务需求整理成结构化、可执行的需求文档。

我准备开发一个“高考志愿填报辅助系统”，请你基于下面的信息，输出一份完整的需求分析文档。

【项目背景】
我希望开发一个支持 PC 和 H5 访问的 Web 系统，在学生获得高考分数后，根据分数、位次、兴趣、城市、院校偏好、专业倾向等信息，为学生提供更适合的高考志愿填报辅助建议。后续我会基于你的输出继续做系统设计、开发计划以及 skill 生成。

【已知需求】
1. 学生在高考出分后输入：
   - 分数
   - 位次或排名
   - 所在省份
   - 选科组合或文理科类别
   - 兴趣方向
   - 目标城市
   - 学校偏好
   - 专业偏好
2. 系统根据这些信息输出：
   - 适合填报的院校范围
   - 适合填报的专业范围
   - 冲、稳、保志愿方案建议
   - 多个备选方案供用户比较
3. 需要结合真实、可靠、公开可获取的招生与录取参考数据
4. 系统需要美观大方，支持 PC 和 H5 访问

【你的任务】
请不要直接进入技术实现，而是先把需求分析清楚。你需要站在产品设计和业务分析的视角，补全当前需求中缺失但必须明确的内容。

【分析要求】
1. 明确项目目标和业务价值
2. 明确目标用户类型与使用场景，例如学生、家长、咨询老师
3. 拆解核心功能模块和子功能
4. 明确推荐流程，从用户输入到志愿方案输出的完整链路
5. 明确需要采集哪些关键用户信息，哪些是必填，哪些是选填
6. 明确数据需求，包括院校、专业、分数线、位次、选科要求、城市信息等
7. 对“冲、稳、保”方案的判定逻辑给出合理定义建议
8. 明确系统应该输出“辅助决策建议”，不能承诺录取结果
9. 明确前端展示需求，包括 PC 与 H5 的关键页面和关键交互
10. 明确非功能需求，包括性能、稳定性、可维护性、可扩展性、数据更新能力
11. 明确风险点、依赖项、免责声明和待确认问题

【特别约束】
1. 输出内容必须贴合中国高考志愿填报场景
2. 必须考虑省份、年份、批次、选科规则差异
3. 不要编造不可验证的数据来源
4. 不能把系统定位成“保证录取”的工具
5. 要强调数据时效性、政策变化和人工复核的重要性
6. 输出要适合继续作为后续系统设计和开发计划的输入材料

【输出格式】
请严格按以下结构输出：

# 项目需求分析

## 1. 项目目标

## 2. 业务价值

## 3. 目标用户与使用场景

## 4. 核心功能需求
- 功能模块
- 子功能说明
- 输入
- 输出
- 业务规则

## 5. 志愿推荐关键流程
- 用户信息采集
- 数据匹配
- 风险评估
- 方案生成
- 结果展示

## 6. 关键业务定义建议
- 冲志愿定义
- 稳志愿定义
- 保志愿定义
- 推荐匹配逻辑定义

## 7. 数据需求与数据来源约束
- 数据类型
- 推荐来源类别
- 更新频率建议
- 数据校验建议
- 政策差异处理建议

## 8. 前端展示需求
- PC 端
- H5 端
- 关键页面
- 关键组件

## 9. 非功能需求
- 性能
- 可用性
- 安全性
- 可扩展性
- 兼容性

## 10. 风险、免责声明与依赖

## 11. 待确认问题清单

## 12. 建议的需求优先级
- P0
- P1
- P2

请使用专业、清晰、可落地的中文输出。
```

---

## 💡 使用建议

- 第一次使用时，先让模型按该模板输出一版完整需求分析
- 第二轮可继续补充目标省份、批次范围、是否支持新高考、是否支持专业优先等规则
- 如果后面要生成 skill，建议保留模型输出中的“关键业务定义建议”“免责声明与依赖”“待确认问题清单”

---

## 🧪 推荐补充参数

如果你后续掌握了更多信息，可以把下面参数补进去，输出会更稳定：

- 适用省份范围：单省 / 多省 / 全国
- 年份范围：近 3 年 / 近 5 年
- 是否支持新高考选科规则
- 是否支持院校优先 / 专业优先 / 城市优先
- 是否支持家长协同查看
