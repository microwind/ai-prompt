## 📌 项目背景

这次实战的重点不是逐章直接生成正文，而是先沉淀 3 份高质量 Prompt 文档，作为后续批量生产、风格统一、生成 skill 的基础输入。

## 🧭 本次实战过程记录

### 第1步：明确内容目标

先把原始需求还原成一个明确目标：

- 以《理解道德经》现有原稿为基础
- 按章节逐篇处理
- 输出简洁版内容
- 适配小红书、微头条、知乎等平台
- 既要保留原意，又要避免过度学术化和过度玄学化

### 第2步：确认原稿结构

原稿目录中已经存在较适合批量处理的章节文件：

- `notes/1.md` 到 `notes/81.md`
- 每章通常包含：原文、译文、逐句解释、心得总结

这意味着后续可以按“单章输入 -> 单章输出”的方式批量生成，不需要先做复杂拆分。

### 第3步：拆分核心任务

把需求拆成 4 组核心能力：

1. **章节内容读取与理解**
   - 读取单章原文
   - 提取章节主题
   - 提炼核心观点

2. **简洁版改写**
   - 保留原意
   - 用现代汉语表达
   - 控制篇幅
   - 适合移动端阅读

3. **平台风格适配**
   - 小红书更偏“轻表达、可分享、可共鸣”
   - 微头条更偏“短、快、观点清晰”
   - 知乎更偏“稍有解释、逻辑更完整”

4. **批量生产与统一规范**
   - 固定输出结构
   - 保持全书风格统一
   - 避免每章风格漂移

### 第4步：将项目拆成 3 类 Prompt

为了方便后续生成 skill 和批量执行，将文档拆成 3 类：

1. **需求提示词**
   - 让模型先澄清目标、边界、风格、平台差异和约束

2. **内容设计提示词**
   - 让模型输出逐章改写规则、输出模板、平台适配规范、质量标准

3. **生产计划提示词**
   - 让模型输出如何批量处理 81 章、如何分批次、如何校对和迭代

### 第5步：约束 Prompt 输出格式

为了后续更容易转成 skill，本次 Prompt 文档统一遵循以下原则：

- 输出结构固定
- 强调“忠于原意，但适合传播”
- 明确平台差异
- 明确篇幅边界
- 避免鸡汤化、营销号化、过度解释

## 🧱 后续如何扩展

未来如果你要继续做《论语》《庄子》《金刚经》或其他经典的短内容版本，也可以直接复用本目录的方法：

1. 先写一个项目 README，记录目标和拆解过程
2. 固定输出 3 份 Prompt 文档
3. 后面再补充批量执行说明、校对规范和发布模板

这样每个内容项目都能形成一套标准化、可复用、可沉淀的 Prompt 教程资产。
