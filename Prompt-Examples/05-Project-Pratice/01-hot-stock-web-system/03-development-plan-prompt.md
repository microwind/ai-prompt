# 🛠️ 热门股票 Web 系统开发计划提示词

> 用于让模型根据需求文档和系统设计文档，输出一份阶段化、可执行的开发计划

---

## 📌 适用场景

当你已经有了需求分析和系统设计结果，希望 AI 帮你进一步拆出实施路线、阶段目标、任务清单、里程碑、风险与验收方案时，可以使用本提示词。

---

## 🎯 Prompt 目标

让模型输出：

- 项目实施阶段划分
- 每阶段任务清单
- 团队分工建议
- 周计划或迭代计划
- 风险控制措施
- 测试与验收标准

---

## ✅ 完整 Prompt 模板

```markdown
你是一位资深技术项目经理，擅长将需求文档和系统设计文档拆解成一份可执行的开发计划，适用于中小团队的软件项目落地。

现在我要开发一个“实时热门股票分析与整理”的 Web 系统。我已经有需求分析和系统设计方案，请你基于这些材料输出一份完整的开发计划。

【输入材料1：需求分析】
{在这里粘贴需求分析结果}

【输入材料2：系统设计】
{在这里粘贴系统设计结果}

【项目目标】
开发一个支持 PC 和 H5 的热门股票分析 Web 系统，能够在开盘、午盘、收盘三个时间段对沪指、深成指、创业板进行热点股票、热门板块和热门题材的数据整理与展示，且数据来源真实、可靠、公开可得。

【规划要求】
1. 将项目拆分为明确阶段，例如：
   - 需求确认
   - 技术预研
   - 基础架构搭建
   - 数据接入开发
   - 热点计算开发
   - 前端页面开发
   - 联调测试
   - 上线准备
2. 每个阶段都要说明：
   - 目标
   - 关键任务
   - 产出物
   - 前置依赖
   - 风险点
3. 输出 MVP 版本优先级，区分“首版必须做”和“二期可扩展”
4. 给出适合 2-5 人团队的角色分工建议
5. 给出周维度或迭代维度的排期建议
6. 给出测试计划，包括功能测试、数据准确性测试、接口测试、兼容性测试
7. 给出上线前检查清单和上线后观察指标

【特别约束】
1. 项目为金融行情信息整理系统，不应输出带有荐股或投资建议属性的功能规划
2. 要重点考虑数据源可用性、交易时段稳定性和数据准确性校验
3. 要考虑 PC 与 H5 的适配开发成本
4. 开发计划要体现“先 MVP，后扩展”的节奏
5. 输出要足够清晰，方便我直接继续转成 skill 或任务清单

【输出格式】
请严格按以下结构输出：

# 开发计划

## 1. 项目实施目标

## 2. MVP 范围定义
- 首版必须实现
- 二期可扩展

## 3. 阶段划分
### 阶段1
- 目标
- 关键任务
- 产出物
- 前置依赖
- 风险点

### 阶段2
- 目标
- 关键任务
- 产出物
- 前置依赖
- 风险点

## 4. 任务拆解清单
- 后端任务
- 前端任务
- 数据任务
- 测试任务
- 运维与上线任务

## 5. 团队角色与分工建议

## 6. 迭代排期建议
- 第1周
- 第2周
- 第3周
- 第4周

## 7. 测试计划
- 功能测试
- 数据准确性测试
- 接口测试
- 性能测试
- 兼容性测试

## 8. 上线前检查清单

## 9. 上线后监控指标

## 10. 风险控制与应对预案

## 11. 验收标准

请使用专业、清晰、可执行的中文输出。
```

---

## 💡 使用建议

- 先用前两份 Prompt 拿到需求分析和系统设计结果，再作为本 Prompt 的输入
- 如果你团队人数、开发周期、技术栈已知，建议一并补充
- 如果你准备后续自动生成 skill，本文件特别适合作为“实施步骤”和“任务编排”的来源

---

## 🧪 推荐补充参数

你可以在输入里追加这些信息，让计划更贴近实际：

- 团队规模：2 人 / 3 人 / 5 人
- 周期目标：2 周 MVP / 4 周 MVP / 8 周正式版
- 是否已有 UI 设计
- 是否已有行情数据接口
- 是否需要后台管理端
