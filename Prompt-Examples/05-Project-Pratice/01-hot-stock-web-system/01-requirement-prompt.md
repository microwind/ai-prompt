# 🧾 热门股票 Web 系统需求提示词

> 用于让模型输出一份完整、可落地、可继续进入系统设计阶段的需求分析文档

---

## 📌 适用场景

当你要开发一个“实时热门股票分析与整理”的 Web 系统，希望 AI 先帮你完成需求澄清、功能拆解、数据边界确认、非功能要求整理时，可以使用本提示词。

---

## 🎯 Prompt 目标

让模型输出：

- 完整项目目标
- 用户角色与使用场景
- 核心功能需求
- 数据来源与可信性要求
- 非功能需求
- 风险、假设和待确认问题

---

## ✅ 完整 Prompt 模板

```markdown
你是一位资深产品经理兼金融数据产品顾问，擅长将模糊业务想法整理成结构化、可执行的需求文档。

我准备开发一个“实时热门股票分析与整理”的 Web 系统，请你基于下面的信息，输出一份完整的需求分析文档。

【项目背景】
我希望开发一个支持 PC 和 H5 访问的 Web 系统，用于分析和整理实时热门股票、热门板块和热门题材，后续我会基于你的输出继续做系统设计、开发计划以及 skill 生成。

【已知需求】
1. 按开盘、午盘、收盘 3 个时间段分别获取沪指、深成指、创业板中：
   - 成交量最活跃的 20 只股票
   - 成交额最多的 20 只股票
2. 根据板块、题材上涨/下跌比例，获取热门板块和题材：
   - 列举 10 个热门板块、热门题材
   - 列举 10 个下跌板块、下跌题材
3. 数据来源要求：
   - 来自证券交易系统以及券商的真实、可靠、公开数据
   - 必须强调数据可信性、可追溯性和合规性
4. 系统形态要求：
   - 开发一个美观大方的 Web 系统
   - 同时支持 PC 和 H5 访问

【你的任务】
请不要直接进入技术实现，而是先把需求分析清楚。你需要站在产品设计和业务分析的视角，补全我当前需求里缺失但必须明确的内容。

【分析要求】
1. 明确项目目标和业务价值
2. 明确目标用户类型与使用场景
3. 拆解核心功能模块和子功能
4. 对“热门股票”“热门板块”“热门题材”的统计口径给出合理定义建议
5. 明确 3 个时间段的业务含义和数据采集时点建议
6. 明确数据来源类型、数据同步频率、数据可信性校验方式
7. 明确前端展示需求，包括 PC 与 H5 的关键展示模块
8. 明确非功能需求，包括性能、稳定性、可扩展性、可维护性、合规性
9. 明确风险点、依赖项和待确认问题
10. 如果存在需求歧义，请主动列出“建议确认项”

【特别约束】
1. 输出内容必须贴合 A 股行情分析场景
2. 不要编造不可获得的数据源
3. 涉及实时数据时，要提醒交易时段、延迟、接口稳定性和合规使用限制
4. 不要给出投资建议导向的表述，系统定位应为“行情分析与信息整理工具”
5. 输出要适合继续作为后续系统设计和开发计划的输入材料

【输出格式】
请严格按以下结构输出：

# 项目需求分析

## 1. 项目目标

## 2. 业务价值

## 3. 目标用户与使用场景

## 4. 核心功能需求
- 功能模块
- 子功能说明
- 输入
- 输出
- 业务规则

## 5. 关键业务定义建议
- 热门股票定义
- 热门板块定义
- 热门题材定义
- 时间段定义

## 6. 数据需求与数据来源约束
- 数据类型
- 推荐来源类别
- 更新频率建议
- 可信性校验建议
- 合规注意事项

## 7. 前端展示需求
- PC 端
- H5 端
- 关键页面
- 关键组件

## 8. 非功能需求
- 性能
- 可用性
- 安全性
- 可扩展性
- 兼容性

## 9. 风险与依赖

## 10. 待确认问题清单

## 11. 建议的需求优先级
- P0
- P1
- P2

请使用专业、清晰、可落地的中文输出。
```

---

## 💡 使用建议

- 第一次使用时，先让模型按该模板输出一版完整需求分析
- 第二轮可继续追加你的数据源范围、目标用户、商业模式等信息做细化
- 如果后面要生成 skill，建议保留模型输出中的“定义建议”“待确认问题”“优先级”三部分

---

## 🧪 推荐补充参数

如果你后续掌握了更多信息，可以把下面参数补进去，输出会更稳定：

- 目标用户：普通股民 / 金融资讯编辑 / 投研助理 / 量化观察人员
- 数据源偏好：交易所公开数据 / 券商公开行情接口 / 合规第三方行情服务
- 更新频率：分钟级 / 5 分钟级 / 交易节点级
- 风格偏好：金融终端风格 / 信息看板风格 / 数据仪表盘风格
